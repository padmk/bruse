# Changelog

## Unreleased

- Pin Runtime object receiver calls to unique page contexts while preserving object groups and callable semantics. Convert zero-isolate node handles for supported DOM, Accessibility and Overlay commands through a pinned call with dialog handling, and refuse unsafe consumers including `DOM.getFileInfo`. Locators enumerate nodes through deep serialization so they work with Chrome 158's zero-isolate handles.
- Pin the pairing state directory in MCP registrations so a client's different `XDG_DATA_HOME` does not select another state directory. Run setup again to update registrations.
- Clarify that page scripts, including agent evaluations and clicks, can close a shared tab with `window.close()` when the browser permits it. Browser and Target commands remain refused.
- Wait for chrome.tabs when checking window ownership and for the updated extension fingerprint after a permission reload. Cap the test suite at four concurrent files to avoid starting every browser at once.
- Bound test CDP requests and reject them on connection close so a missing reply cannot leave a test body waiting forever. Test browser cleanup moves temporary directories to Trash and browser launches disable macOS app cloning.

## 0.19.1

- **Shared tabs stay open:** agents cannot close or discard a tab you shared, also not through raw DevTools commands. They can still use, reload and navigate it. Agents still close their own tabs, and tabs still close when a session ends. In "all tabs" mode nothing changes.
- **Setup survives a browser folder it cannot write:** it names each folder that failed and goes on, and stops with a clear message only when no folder could be written, or when the host would not start (for example a wrong Node path), instead of waiting 10 minutes for an extension that cannot pair.
- **Setup closes the gap while an older hub still runs:** it creates the pairing secret when it registers the host, so a 0.18 hub of an agent session started earlier no longer accepts a secret from another local program. An existing secret is kept. Doctor now says "Native pairing secret exists", which does not mean an extension has connected.
- **A program holding the hub port cannot start many hosts:** the extension answers one challenge per connection, so a flood of challenges no longer starts a Node process for each.
- **Uninstall keeps the hosts with a kept installation:** hosts are removed only after the installed folder has moved, and one that cannot be removed is listed with the other paths left in place, without stopping the uninstall.
- **Help for an older extension:** while waiting, setup says to click Reload on an extension that is already loaded, because setup cannot reload one that never paired.
- **Chrome for Testing:** setup and uninstall also cover `Google/ChromeForTesting` on macOS and `google-chrome-for-testing` on Linux, the locations in Chrome's documentation.
- **Correction to 0.19.0:** uninstall on Linux no longer collides with an earlier entry in the Trash, because each entry gets a unique name. This shipped in 0.19.0 but was not listed.

## 0.19.0

- **Pairing through a native host:** the extension now gets its secret from a native messaging host that the browser starts only for this extension, so no secret crosses the hub port, even on first use. A program that took the port first gets nothing and cannot drive the extension. Setup registers the host for Brave, Chrome, Edge, Chromium and Vivaldi, uninstall removes it, and doctor says how to repair it.
- **No pairing reset:** a reinstalled extension gets the existing secret by itself, so the reset question in setup and the errors about pairing offers are gone.
- **Update:** run `bruse setup`. Existing pairings keep working. An older extension that never paired must be updated.

## 0.18.9

- **Shared tabs keep their place:** agents cannot pin, unpin, move or group a tab you shared, or a group holding one; sharing lets them use the tab, not rearrange your tab strip.
- **A pairing reset accepts one secret:** after a yes in setup, the hub moves the stored secret and accepts only the secret that was on offer. When two programs offer different secrets, setup stops, keeps the pairing and says to find out what the other one is. The question now says that another program could have caused it.
- **Partial uninstall keeps the pairing:** when the installed folder cannot be moved to the Trash, the pairing state inside it stays too. A state directory elsewhere is still moved.
- **Doctor on a damaged installation:** a missing or broken extension or server file gives one problem line and a non-zero exit, without a crash and without a "Connected" check.
- **Uninstall wording:** the note says to remove the extension in the browser it was loaded in, because the page it opens is that of the first browser installed.

## 0.18.8

- **Uninstall no longer removes the extension by itself:** no browser dialog can be shown for a request from the background, and a silent removal would be open to any agent, so `extension.uninstall` is gone. `bruse uninstall` opens the extensions page and says to remove the extension there.
- **Uninstall reports what it could not move:** a failed move to the Trash names the path that is left and exits with an error.
- **Setup reports a refused pairing instead of waiting:** when a new extension offers to pair though a pairing exists, setup asks in a terminal whether to reset it, and without a terminal stops and says the user must decide. An extension left over from an uninstall gets a message to remove it, load it again and run setup. The hub accepts nothing it refused before.
- **A damaged installation stops setup:** when the extension's code fingerprint cannot be computed, setup stops and `bruse doctor` reports a problem, instead of accepting any connected extension of the same version.
- **Agent instructions limit what an agent clicks:** only Developer mode and Load unpacked on the extensions page, only the printed path, stop at any unexpected window, and never answer the pairing question for the user.
- **Chrome Web Store copy:** the README says to remove a 0.17.0 copy from the store before loading the unpacked one.

## 0.18.7

- **Agent clients sorted by name:** setup and doctor list them alphabetically, so Claude Code and Claude Desktop are next to each other.
- **Setup names an agent session that holds the port:** after an uninstall, an earlier session's server keeps the hub port without a token setup can check; setup now says to restart those sessions instead of pointing at an unknown program.

## 0.18.6

- **Clearer first install:** setup lists the exact clicks for loading the extension, and in a terminal on macOS puts the folder's path on the clipboard for the Load unpacked dialog. The agent instructions work from a Homebrew install as well as from a package, and let an agent with a desktop control tool do the clicks with the user's permission. The README has a prompt for asking an agent to install Bruse.
- **No Chrome Web Store:** Bruse is distributed only through Homebrew, release zips and checkouts. The hub no longer accepts the store's extension ID, and the store's code paths and listing files are gone.

## 0.18.5

- **Uninstall removes the extension:** `bruse uninstall` asks the connected extension to remove itself, and tells you to remove it on the extensions page only when it is not connected, is paused, or stayed.
- **Setup and uninstall say why an agent CLI failed:** when a CLI crashes without printing anything, the message names the signal or exit status instead of showing empty parentheses.

## 0.18.4

- **Doctor and setup report a browser that cannot protect the extension's storage:** when the extension could not keep its storage from content scripts and so refuses agent requests, `bruse doctor` reports it as a failed check and `bruse setup` stops with it, both saying to update the browser, instead of reporting that everything is ready.
- **Setup decides on fresh state:** setup checks the extension's state (paused, storage problem) once more right before it reports that Bruse is ready, so a pause switched on while setup reloaded the extension is not missed.
- **A pause during a session's end keeps its tabs:** the extension reads the pause switch from storage each time instead of from a copy that changes a moment after the click, and checks it again right before it closes a session's tabs; a session whose end was under way when you paused keeps its tabs until you resume.

## 0.18.3

- **Pause keeps everything still:** while agents are paused, a session that ends (its server sends `session.end`, or it drops off the hub's report) closes none of its tabs; they close when you resume, unless the session came back meanwhile. `extension.reload` is refused while paused, because a reload ends your tab shares; `bruse setup` stops and asks you to resume agents, also when the extension needs no reload. Pausing ends download waits in progress, also one whose request was still being checked. Agent tabs that the browser restores after a restart are no longer tied to a session and stay as your tabs.
- **Sharing a tab is not sharing its window:** changing, closing or focusing a window, moving tabs or groups into it and switching its active tab need every tab in the window to be the session's own; a window whose tabs you shared stays visible to the agent but is not its to change.
- **Storage protection fails closed:** if the browser does not let the extension keep its storage from content scripts, agent requests fail with a message to update the browser, and `browser.info` reports the problem.
- **Duplicating keeps your tab choice:** after `tabs.duplicate` the previously active tab comes back only while the duplicate is still the active one, so a tab you switched to meanwhile stays in front.
- **Setup tolerates a failed clean-up:** when the previous installation cannot be moved to the Trash after a successful update, setup names the leftover folder instead of failing.

## 0.18.2

- **Fixed, raw DevTools commands reached extensions' script worlds:** when the extension removed another extension's frame from a page, it ran its own script there in an isolated world with the extension's storage and messaging, and an agent's raw `Runtime` commands could name that world, or another extension's content-script world, by context ID or object handle. Raw commands now run JavaScript and use objects only in the page's own contexts: a numeric context ID of `Runtime.evaluate` or `Runtime.callFunctionOn` is sent as that context's unique ID (which a new renderer process does not reuse), other numeric context IDs, `executionContextName`, `Runtime.addBinding` and `Runtime.disable` are refused, and object handles must belong to a page context. The extension's storage is open only to its own pages, and its service worker and offscreen document take messages only from each other.
- **Only about:blank and about:srcdoc:** other `about:` addresses, which the browser turns into its internal pages (`about:settings` opens `chrome://settings`), are refused like those pages.
- **Hidden tabs reveal nothing:** a request for a tab the session may not use fails with the access error before the tab's address is checked, so the error no longer names the scheme of the page in it.
- **Agent tab group named after the extension:** the group of agent tabs is titled with the extension's name, in grey, instead of "Claude" in orange, which read as another product's group.
- **Hub limits for unauthenticated connections:** control frames over 125 bytes or fragmented close the connection, as RFC 6455 requires, and a connection that has not authenticated and leaves more than 64 KiB of the hub's replies unread is closed.
- **Hub token stays private:** the hub writes its token to a new file readable only by the user and moves it into place, and sets the state directory to the user only, also when they existed with wider permissions.
- **The js tool says what it runs:** its description says that the code runs as Node.js on the user's computer with the user's permissions.
- **Restore command quoting:** the command that setup prints to restore a kept installation quotes paths in single quotes, so the shell does not expand `$` or backquotes in them.

## 0.18.1

- **Agents stay out of your windows:** in the default access mode a window is a session's only when every tab in it is the session's or shared. Management calls change, focus or remove only such windows (`windows.update`, `windows.remove`), move tabs and groups into another window only when it is the session's (`tabs.move`, `tabs.group`, `tabGroups.move`), add tabs to a group only when the session reaches every tab in it, and activate, highlight or unhighlight a tab only in the session's windows, so an agent cannot switch the tab you are looking at. `windows.get`, `getAll`, `getCurrent` and `getLastFocused` leave out windows without a tab the session reaches.
- **Tabs that management opens are the agent's:** a tab from `tabs.duplicate` or `windows.create` belongs to the session like one from `createBrowserTab`: it joins the agent group, opens in the background (a new window opens unfocused unless `focused` or a maximized or fullscreen state is given) and closes when the session ends, also when the session ends while the window is being created. A tab moved into a new window with `tabId` keeps its owner or share. Such tabs had belonged to no session, so the agent could not use them and they stayed open.
- **Failed updates put the previous installation back:** when `bruse setup` cannot move the new copy into place, it restores the previous one and stops; if that fails too, it keeps the backup and prints the command that restores it. A process killed between the two renames can still leave no copy in place.
- **Setup says whom Bruse is for:** the first `bruse setup` (not updates) says, before registering the MCP server, that Bruse is meant for agents you trust, that code in the `js` tool runs with your account's permissions, that agents can use the accounts signed in to your browser profile, and that a separate profile keeps those out of reach but is no sandbox.
- **Docs:** the README and `SECURITY.md` describe these rules, and that actions of several agents on one shared tab can interleave.

## 0.18.0

- **Measured on public websites:** six tasks on Wikipedia, GitHub, the Python documentation, a paginated shop and TodoMVC, 8 runs per tool: Bruse's median run took 48 to 68 % less time and 38 to 74 % less money than Claude in Chrome, all 96 runs passing, in Brave on the code before the last fixes to replaced elements and tab shares (see `bench/README.md`). The `existing-tab` task now expects both tools to keep a tab the user did not share private.
- **Setup checks the hub port before pairing:** before you load the extension, `bruse setup` stops unless a hub that knows the hub token holds `127.0.0.1:47615` (its own or an agent session's); a new extension gives its pairing secret to whatever answers there, and a program on the port had let setup wait while the extension paired with it.
- **Docs say what Bruse does not do:** the README no longer leads with the benchmark pages' numbers; it says who Bruse is for, how updates work, that a managed browser may block it, that tab isolation is neither account isolation nor a sandbox, why there is no site allowlist and why `fetch` stays in the REPL, and that no independent audit has been published. `bench/README.md` states what the numbers cover and how the earlier results were put together.
- **Two more benchmark tasks:** an order the server rejects twice (postal code format, then stock) until the agent corrects it from the server's messages, graded by the one order the server accepted; and a bar chart drawn on a canvas, whose values are not in the page's text or accessibility tree.
- **Benchmark runs prove they used the browser:** a Claude Code run passes only when its answer is right and its conversation shows browser calls, a connected extension and no Bruse code that reached pages from Node.js (`fetch`, imports, processes); the record says which check failed and how much time went to tool calls. Codex conversations are saved too, and each result folder gets `meta.json` with the commit, the agent's and Node's versions and the extension the browser ran, which must be this checkout's code (the runner reloads it once if not).
- **Setup and doctor see stale extension code:** the extension reports a fingerprint of its code in `browser.info`. `bruse setup` waits until the reloaded extension runs the installed copy's code, not only its version, and `bruse doctor` reports a browser that still runs other code of the same version, as after an update without a reload or with the extension loaded from another folder. The fingerprint leaves out the manifest's distribution fields (`key`, `update_url`) and its formatting, so the Chrome Web Store package and the browser's copy of it match the folder they were built from; any other manifest or code change counts.
- **Fixed, release zip:** the zip left out `installer/clients.mjs`, so its `bin/bruse.mjs` and **Install Bruse.command** failed at once with a missing module (0.17.0 is affected; Homebrew installs are not, as they build from the source archive). The zip now carries every installer module, and the release check loads each of them.
- **One grading rule for both benchmark suites:** the tasks on the benchmark's own pages are graded like the public-site tasks: every number in the answer, apart from the ones the question names, must be the expected value, so an answer such as "18 552,95 or 18 553,95" or "-18 552,95" no longer passes. Regrading the 268 stored runs changes none of them.
- **Smaller page state:** image source URLs are left out of the accessibility tree, and tooltips are cut to 80 characters and left out when they only repeat the page a link leads to. The first state of Wikipedia's main page is about 10 % shorter, a GitHub folder about 27 %.
- **No workaround without the extension:** when the extension is not connected, the error points to `bruse doctor`, and the `js` tool's description tells agents to stop and tell the user instead of doing the task another way, such as fetching pages from the REPL; without this, a session could finish a task slowly without the browser at all.
- **Uninstall says what is left:** `bruse uninstall` ends with the steps it cannot do itself: removing the extension, `brew uninstall bruse` after a Homebrew install, and restarting agent sessions that still run the removed server. The README lists them too.
- **Agent tab group starts collapsed:** the tabs of all agent sessions take one chip in the tab strip until the user opens the group.
- **Agent tabs stay loaded:** the browser no longer discards agent tabs to free memory, which emptied the page and what the agent had typed into it while the agent kept working on it; a tab that was discarded anyway (a tab the user shares, or one discarded by hand) fails with a message that says so and how to load it again, instead of a script error on an empty page.
- **Agents use their own tabs and the tabs you share:** by default an agent session sees and uses only the tabs it opened (and tabs their pages opened from its input) and the tabs the user shares with **Share this tab** in the toolbar popup. Other tabs are hidden: listings leave them out and say only how many there are, and binding, reading, driving, closing or rearranging them (also through the management capability) fails with a message that tells the agent to ask the user to share the tab. Sessions cannot reach each other's tabs. The extension decides by the session the hub names for each request, not by one a request names. Stopping a share, or switching from all tabs to agent tabs, detaches the debugger from tabs no session may use at once; an agent that waits for a download from that tab does not get the file, also when the download has completed and the extension is still looking it up. Changes to the shares are made one at a time across the popups and the service worker, so stopping two shares at once, or while a shared tab closes, ends both. **Access** in the popup lets agents use all tabs, as before. An MCP server older than this extension gets an error that asks the user to run `bruse setup`.
- **Raw DevTools commands by allowlist:** raw commands are limited to domains that act on the page in the tab (Accessibility, Animation, CSS, DOM, DOMSnapshot, Emulation, Input, Log, Network, Overlay, Page, Performance, Runtime), still without cookie and cache commands and `Page.addScriptToEvaluateOnNewDocument`, and a frame's session works only with the tab it belongs to.
- **Replaced elements:** an action on an element number whose element a page script has replaced since the snapshot (Wikipedia's search field becomes a combo box after load) acts on the element that took its place, also when the number comes from an earlier read of the page that a later read no longer shows. That happens only when the page has not navigated, the old element was the only one of its name and role in its document at that read, and exactly one element of that name and role is there now, one the page added after the read (not one it already had, even hidden). Otherwise the action fails with the stale-element error, so removing one of two "Delete" buttons never sends a click to the other. Agents had got a stale-element error and spent extra calls on a new state; a Wikipedia search took 7 to 8 turns instead of 4.
- **Pages, not the browser:** the extension lets agents open and drive web pages (and blank, data and file pages) only, not the browser's internal pages or the extension's own pages, and refuses the raw DevTools commands that reach other targets (`Target`, `Browser`, `SystemInfo`), the cookie store and the cache (`Storage` and `Network`'s cookie and cache commands), certificate checks (`Security`), or scripts registered to run in the next page the tab loads. An agent can no longer open the popup's page and change the user's settings.
- **History and bookmarks are optional:** the `history` and `bookmarks` permissions are off until the user turns them on under **Access** in the popup; an agent that needs them is told so.
- **Setup asks which clients:** `bruse setup` lists the agent clients it finds and registers the MCP server with the ones the user picks (Enter picks all); `bruse setup --clients claude-code,codex` picks without asking. Without a terminal and without `--clients`, an update keeps the clients that already have the server and a first install stops with the list, instead of registering with every client found. `bruse doctor` no longer counts a client the user left out as a problem.
- **Fixed, pause switch:** the popup stores a pause or resume before showing it, so closing the popup right after a click no longer loses it.
- **Benchmark on public websites:** `node bench/run.mjs --suite real` runs tasks on Wikipedia, GitHub, the Python documentation, a paginated shop and a single-page app, and saves every run's conversation; `bench/report.mjs` shows 95 % bootstrap intervals.
- **Clicks wait for the page they open:** a click or key press that starts a navigation (a link, a form submission) returns once the new page has loaded, as in Playwright, and a state read right after an action no longer shows the new page half parsed. Agents had read a page with only its banner after submitting a filter and then spent a separate call on every read.
- **Date fields:** `setValue()` on the day, month or year of a date input sets the whole field, and a value the field rejects fails with the format it takes (such as `2026-11-03`) instead of leaving the field empty.
- **Fewer calls:** the tool description makes `createBrowserTab("1", url)` the first call when the agent opens a page, which also returns the documentation; agents had spent a call on `getState()` first. The documentation shows how to check many elements in a loop within one call.
- **Install docs:** the README leads with `brew install padmk/tap/bruse`, and `bruse help` and the Homebrew notes name all the agent clients setup registers with.
- **Fixed, killed sessions:** the tabs of a session whose MCP server was killed (for example with SIGKILL while it was the hub) no longer stay open for good. The hub reports the live sessions to the extension, servers reconnect as soon as their hub goes away, and a session that owns tabs and stays off the report for 45 s ends like any other: its unmarked tabs close and its marked ones stay. Without a hub, nothing is closed.
- **Fixed, session cleanup:** a tab that was still being created when its session ended is closed once it exists, instead of staying open with no live session to close it.
- **Fixed, password managers:** a password manager menu (another extension's frame) no longer blocks a tab for good. State reads such as `getAXState()` recover from it like commands do; removal scripts each frame of the page on its own, finds known password manager wrappers also inside shadow roots, checks whether the frame came back and is retried up to three times, and a call that still fails says what removal did. A command for a cross-origin frame after the debugger attached again goes to the frame's new session.
- **MCP servers authenticate the hub:** a server that connects to the hub no longer sends the hub token; server and hub prove it to each other with HMAC over fresh nonces, and the server sends no request until the hub has proved it. A process of another user that takes the port after the hub exits gets neither the token nor any request. A hub of this version still accepts older servers, which present the token as before, so agent sessions started before the update keep working. A newer server that finds an older hub on the port reports that the versions differ, and `bruse setup` stops with that message until the agent sessions started before the update are restarted.
- **Hub limits unauthenticated connections:** until a connection has authenticated, the hub takes messages of at most 8 KiB from it and keeps at most 32 such connections; the 64 MiB limit applies only after authentication. A connection whose peer ended its side is closed at once.

## 0.17.0

- **New look:** a new icon, and the toolbar popup shows the extension's state with a status dot and one clear button.
- **Chrome Web Store:** the MCP server accepts the extension from the Chrome Web Store as well as an unpacked copy; setup and doctor let the store update its copy instead of asking to reload it. `node scripts/store-package.mjs` builds the store package.
- **Privacy policy:** `PRIVACY.md` describes what the extension accesses, where it goes and what is stored.
- **`bruse` command:** `bruse setup` installs or updates the extension files and the MCP server, registers the server with Claude Code and Codex and waits for the extension; `bruse doctor` checks the installation, the registrations, pairing and the browser connection and says what to run for each problem; `bruse uninstall` removes what setup added; `bruse version` prints the version.
- **Setup reports failures:** setup exits with an error when an agent CLI rejects the registration, and after reloading a connected extension it waits until the extension reconnects with the new version, so an extension loaded from another folder or turned off is reported instead of a false success.
- **More agent clients:** setup registers the MCP server with Cursor, VS Code (and Insiders), GitHub Copilot CLI, Gemini CLI, Claude Desktop, Devin Desktop and Windsurf, besides Claude Code and Codex; `bruse doctor` checks those registrations and `bruse uninstall` removes them. JSON configurations keep every other setting, are backed up first, and are left alone when they contain comments.
- **Pause switch:** the Bruse icon in the toolbar opens a switch that pauses agents: the extension detaches from every tab and refuses agent requests until the user resumes. Cancelling the browser's debugging bar pauses too, and `bruse doctor` reports a paused browser.
- **Hub checks the host name:** WebSocket upgrades must address `127.0.0.1` or `localhost`, so a page using DNS rebinding cannot reach the hub even before the token and origin checks.
- **Tests:** `npm test` runs unit tests and end-to-end tests that load the extension into headless Chromium and check pairing and authentication, session cleanup, page actions, locators, frames, dialogs, downloads and the `bruse` command cycle; CI runs them on every push.
- **One folder:** the installed copy and the pairing state live in `~/.local/share/bruse` (or `$XDG_DATA_HOME/bruse`) on macOS and Linux alike, instead of `~/Library/Application Support/Bruse` and `~/.local/state/browser-control`.
- **Versions:** the MCP server reports the release version, the extension reports its version, and an agent is told once when the two differ (for example after an update before `bruse setup`).
- **Fixed, pairing:** after reinstalling the extension, removing `extension-secret` lets it pair again. Before, the new extension kept a secret the hub had refused and could not pair until it was reinstalled once more.
- **Fixed, hub:** a malformed authentication message (a MAC with non-ASCII characters) no longer ends the hub process; the connection is refused.
- **Fixed, exports:** YouTube transcripts and Google Workspace exports go to a directory only the user can read, and a second export with the same name no longer replaces the first.
- **Fixed, REPL:** a declaration on the line after `count++` or `count--` persists to later cells.
- **Fixed, keys:** `ControlOrMeta` in locator `press` and `click` is Control outside macOS, and `tab.pressKey` accepts it too.
- **Fixed, downloads:** a `target=_blank` link to an attachment that the server answers at once counts for the waiting tab again (the new tab closed before its opener was looked up), and a tab the agent creates right after a page opened one no longer holds back its downloads.
- **Fixed, selected tab:** `browser.tabs.selected()` returns the active tab of the window the user used last, not the active tab of whichever window comes first.
- **Release zip:** it includes SECURITY.md and CHANGELOG.md, and README links to files it leaves out point to the repository.
- **Fixed, MCP:** a JSON line that is not an object (such as `null`) is ignored instead of ending the server.
